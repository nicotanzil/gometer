GoMeter 0.8.0 refreshes the dashboard workspace and adds an explicit option for
HTTP worker control on trusted networks.

- The dashboard has a collapsible sidebar, mobile navigation, clearer builder and
  results layouts, and updated screenshots and walkthrough media. Keyboard
  shortcuts cover navigation, validation, saving, starting a run, and canvas undo;
  the in-app reference opens with `?`.
- Remote worker control can use HTTP when both sides opt in: workers set
  `GOMETER_WORKER_ALLOW_HTTP=true` (or `-allow-http`), and the dashboard or CLI
  coordinator sets `GOMETER_ALLOW_HTTP_WORKERS=true` (or
  `-allow-http-workers`). The shared worker token remains required. Verified
  HTTPS remains the default.
- The optional `k8s/http-workers` overlay removes worker TLS Secret mounts for
  deployments that intentionally use HTTP control. The standard Kubernetes
  manifests continue to use verified HTTPS.

HTTP control sends the token and test configuration without application TLS.
Use it only where network access is restricted and you accept that exposure.
Existing saved worker URLs do not grant the opt-in; each process must be
configured at startup. The Kubernetes manifests are examples and have not been
verified on a live cluster. This release publishes executable archives and
checksums; build and push the container image separately before deploying it.
